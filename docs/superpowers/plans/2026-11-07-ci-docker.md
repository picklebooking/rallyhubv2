# CI, Lint Gates and Docker Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Codex:** if those skills aren't available, execute the tasks in order. Run each task's verification commands before its commit, and don't start a task until the previous one's gate passes.

**Goal:** Close audit findings #11 (Compose web cannot reach the API) and #12 (nothing checks a PR): make API and web lint real gates, declare Turbo build env, fix Compose routing, and add one advisory CI workflow, as specified in the design.

**Architecture:**
- **Lint gates:** API lint becomes read-only (`lint`, plus a `lint:fix`), ignores generated/build output, and reaches 0 errors (one auto-fix commit, one hand-fix commit). Web lint runs with `--max-warnings 0` after its 15 warnings are fixed; `eslint-plugin-only-warn` stays.
- **Turbo env:** `turbo.json` `build` declares `API_INTERNAL_URL` and `NEXT_PUBLIC_*` so `next build` under Turbo bakes the real proxy origin.
- **Compose routing:** web gets `API_INTERNAL_URL=http://api:${API_INTERNAL_PORT:-3000}` and a same-origin `NEXT_PUBLIC_API_URL` default; the Axios fallback becomes `/api/backend`.
- **CI:** one `.github/workflows/ci.yml` with two jobs, `checks` (lint, typecheck, build, OAuth helper test) and `api-tests` (Postgres 17 service, `migrate deploy`, full Jest). A Jest global-setup guard fails any CI run that lacks `TEST_DATABASE_URL`.

**Tech Stack:** npm 10 workspaces, Turborepo 2, ESLint 9 flat config (typescript-eslint, eslint-plugin-prettier, eslint-plugin-turbo), Next.js, NestJS 11 + Jest (ts-jest ESM), Prisma 7, GitHub Actions, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-07-ci-docker-design.md`. Read it first. Every decision in it is final; this plan only fixes what it left to the builder, plus the rulings listed under "Plan rulings".

## Plan rulings (where the spec was silent or slightly off)

1. **Prettier check scope.** The spec says `npm run prettier:check` must report no `apps/api` files after the fix. It will still report the tracked `apps/api/.agents/**` markdown (63 files), `apps/api/eslint.config.mjs` and `apps/api/prisma.config.ts`, which ESLint doesn't cover. Ruling: the expectation is **no `apps/api/src/**` or `apps/api/test/**` files**. Don't reformat the others (churn).
2. **Web ESLint config** is `apps/web/eslint.config.js`, not `.mjs`. Irrelevant to the fix, which goes in `packages/eslint-config/next.js` as the spec says.
3. **CI run proof.** The spec says CI is proven by the run on PR #34; that needs a push, which this plan forbids. The executor validates the YAML locally and reproduces every CI step; the PR run URL is recorded at ship time by whoever pushes.
4. **`DATABASE_URL` in Turbo.** `prisma.config.ts` reads `process.env["DATABASE_URL"]` (not Prisma's `env()`), so `prisma generate` doesn't need it. Leave it out of `turbo.json` unless Task 2 Step 4 proves otherwise.
5. **Usage-chart sample values** are fixed here (Task 3) so the reviewer has one thing to check.
6. **Migration authorization:** recorded in the spec's Docker step 2 (updated 2026-11-07) and in Global Constraints above.

## Review Focus

1. **`npm run lint -w api` must never write.** A file with a fixable Prettier error stays byte-identical after lint, and lint exits non-zero. Pinned in Task 7 Step 2.
2. **A CI job that runs API Jest without `TEST_DATABASE_URL` must fail, not skip green.** Outside CI, the same run still skips. Pinned in Task 4.
3. **A Turbo build must bake the env's `API_INTERNAL_URL`** into `routes-manifest.json`, not the `localhost:3001` fallback. Red-then-green in Task 2.
4. **The usage chart renders identical values on server and client.** No `Math.random`/`Date.now` in the hook; the lint purity rule is the pin (Task 3), plus a web build.
5. **The renamed OAuth helper test must still fail when its assertion fails** (a broken `.mts` that silently exits 0 would be a fake gate). Pinned in Task 3 Step 4.
